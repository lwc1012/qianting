# 海水密度参数化 —— 算法敏感性实验报告

本报告回答一个问题：把 Main.qml 里那个写死的 `waterDensity = 1.02` 换成从 WOA23 算出来的真实海水密度，**会不会改变算法给出的决策**。

### 0.1 算法复刻的校验（必做，否则后面所有数字都不可信）

复刻是否忠实不能靠「看起来对」。本实验用**解析判据**校验：

`solve_rescue()` 的排水分支只由所需排水量 `need_L = W/ρ` 与一组固定容量阈值的比较决定——不用尾组时跨过各救生舱组的累计容量，用尾组时跨过 600 L 以及 `600 + 累计容量`。因此当 ρ 由 1.020 变到 1.0276 时，**发生翻转的载荷 W 必须落在 `[T·ρ₁, T·ρ₂]` 这个窗口内**（T 为上述阈值之一）。

两个细节决定了阈值要对齐：循环开头的 `if (remaining_needed_L <= 0.01) break;` 意味着每组的启用阈值带 **+0.01 L 的容差**；而 `total_lifeboat_water >= need_L`（是否动用尾组）与 `(lb_total + 600) < need_L`（是否动用指挥舱）是**精确比较**。

压铅则要看**格点区间**：压铅取的是「使 `total + delta ≥ 0` 的最小 delta」，等价于取 delta 格点集合中 ≥ `need = -total` 的最小格点。need 由 need₁ 漂移到 need₂ 时，选择改变 **当且仅当有格点落在 [need₁, need₂) 内**。

| 校验项 | 结果 |
| --- | --- |
| W 细网格样本数（3 种舱态 × 901 个载荷 × 3 种乘员排布）| 8109 |
| 排水分支翻转处数 | 189 |
| 其中落在解析阈值窗口内 | **189 / 189** |
| 压铅翻转处数 | 131 |
| — 其中与排水分支同步变化（不计入判据）| 19 |
| — 其余符合格点区间判据 | **112 / 112** |

**全部翻转点都能被解析判据解释，命中率 100%**，说明复刻与 Main.qml 的行为一致，后续翻转率数字可信。

> 这个校验不是走过场：第一版校验里我把阈值集合写漏了（只写了 570/712.5/855/997.5，漏了 142.5/285/427.5/600 等），命中率只有 15%；把压铅判据写成「need 距下方最近格点的距离」也是错的，命中率 83%。两处都改正后才达到 100%。

## 3 实验三：水面模式（solve_departure）

| 水舱状态 | 压铅翻转 | 最大力矩差(kg·m) | 样本数 |
| --- | --- | --- | --- |
| 全满舱（救生舱+指挥舱，程序默认） | 0/1500 | 0.000 | 1500 |
| 救生舱满、指挥舱空 | 0/1500 | 9.732 | 1500 |
| 救生舱半舱、指挥舱空 | 0/1500 | 4.786 | 1500 |
| 救生舱1/4舱、指挥舱空 | 0/1500 | 2.313 | 1500 |

**这是本次实验最直接的一个结构性发现**：程序默认水舱是**满舱**（救生舱 4×142.5 L，指挥舱 215+215=430 L，见 Main.qml L461-462），此时每一舱的 `missing = 容量 - 当前 = 0`，`solve_departure()` 里所有含密度的项都被 `if (missing > 0.01)` 挡掉了——**密度根本不参与任何运算，换什么密度结果都逐位相同**。

只有水舱不满时密度才进入计算。注意表中「救生舱满、指挥舱空」一行还有 9.7 kg·m 的力矩差，它**完全来自指挥舱水舱**（430 L × Δρ × 2.969 m），与救生舱组的充装状态无关。即便这样，这个量级仍然小于移动最小的一块压载铅（53.2 kg·m）。

## 4 实验四：误差折算

ρ 由 1.020 变到真实上界 1.0276 kg/L（Δρ = 7.62 kg/m³，相对 0.75%）时：

| 物理量 | 力矩变化(kg·m) |
| --- | --- |
| 尾组全排空 600 L 的力矩 | +17.55 |
| 救生舱组1满舱 142.5 L 的力矩 | +1.35 |
| 救生舱组2满舱 142.5 L 的力矩 | +2.10 |
| 救生舱组3满舱 142.5 L 的力矩 | +2.85 |
| 救生舱组4满舱 142.5 L 的力矩 | +3.60 |
| 指挥舱满舱 430 L 的力矩 | -9.73 |

压载铅移动一块的力矩台阶：[53.2, 55.2, 108.4] kg·m

→ 密度常数误差带来的力矩偏差（最大 17.6 kg·m）**小于移动一块压载铅的最小台阶 53.2 kg·m**。

| 获救人员总重(kg) | 排水读数@1.020(L) | 排水读数@真实(L) | 差(L) |
| --- | --- | --- | --- |
| 300 | 294.12 | 291.94 | 2.18 |
| 600 | 588.24 | 583.87 | 4.36 |
| 900 | 882.35 | 875.81 | 6.55 |

排水量读数 `W/ρ` 的相对偏差恒等于 ρ 的相对偏差 （**0.75%**），与载荷大小无关。

## 5 结论

1. **水面模式**：密度是死代码。默认满舱时 `missing=0`，ρ 完全不进入运算；改成真实密度不会改变任何输出。
2. **水下救援模式**：密度通过两条路径进入——所需排水量 `W/ρ`，以及力矩损失 `V·ρ·L`。
3. **绝大多数工况下结论不变**：逐条代入 276 条真实密度后，决策发生变化的比例只有 **1.13%**（压铅 0.96%，排水分支 0.30%）。
4. **但变化的那一小部分是危险的**：排水分支一旦翻转，力矩损失突变可达 **1688 kg·m**，相当于约 **32 块压载铅**的调节能力——这是量级完全不同的决策差异。
5. 因此**结论不是「密度不重要」，而是「密度的作用集中在少数临界工况上」**。那些工况恰恰是救援中最需要算准的情形。

> 注：本实验只检验**决策是否改变**，不检验决策的**物理正确性**。算法本身是否合理不在本次实验范围内。
